# Section Sandbox (18.5)

## TL;DR
**Phase:** Concept Lab (DNA Lock)  
**Change Budget:** LARGE (sandbox files only; no production edits)
**Input:** active-dna.md v1 + moodboard output + brief + curated images  
**Output:** modular `.lab.html` files + `direction-merge.html` + `dna-diff.md` + active-dna.md v2  
**Stop:** after 3 cycles → selection required  
**Redirects:** if production work requested → go 19/production pipeline; if bug → 15
**Sandbox Fidelity Contract**

Must match: layout geometry, spacing rhythm, typography scale, component composition.

May approximate: lighting/3D depth, parallax, blur/noise fidelity.

Forbidden in sandbox: WebGL/R3F, GSAP timelines, complex scroll triggers.

If reference relies on shader/WebGL effects, state this explicitly and provide a CSS approximation plan.

---

## Objective
Turn moodboard inspiration into real structural decisions.

This skill is where major design pivots are allowed:
- round ↔ sharp
- minimal ↔ editorial
- single image ↔ collage/gallery
- glass ↔ hard border
- sparse ↔ dense

After this skill locks DNA v2, production must not redefine identity.

---

## When to Run
- After moodboard approval
- When direction is not locked
- When structure/density/image strategy is unclear
- Before Section Prototyper (19) and before production builds

---

## Inputs
- `.agent/design/active-dna.md` (v1)
- moodboard output (refs, notes)
- brief essentials (goal, audience, conversion)
- user-curated image folder (local assets)
- Prompt Bible (pre-filled)

/sandbox/

- dna-diff.md

Also:
- Update active-dna.md to **v2**
- Append new vocabulary terms to Prompt Bible (non-destructive)

---

## Sandbox Implementation Rules
Sandbox uses:
- Pure HTML
- CSS variables
- Minimal JS only for variant toggles

Do NOT use:
- React
- framework abstractions
- production component architecture
- performance optimization

The sandbox is disposable by design.

---

## Variant System
Each `.lab.html` contains 2–5 variants max:
- A, B, C, D, E

Each variant must include:
1) A style name  
2) Axis classification  
3) “Why it exists” (3 bullets tied to brief)

If a variant cannot be named and justified → it is invalid.

---

## Mandatory Design Axes
Each variant must declare:
1. Structural Archetype
2. Visual Density
3. Typography Energy
4. Image Strategy
5. Surface Language
6. Motion Intent (descriptive only)

---

## Image Rules
Images are provided by the user.

Allowed:
- up to 7 images in hero
- collage/cluster/masonry/grids
- overlays (vignette/gradient/grain)
- cropping and scale changes

Not allowed:
- web-searching assets
- inventing new image themes outside the provided pack

---

## Iteration Cycles (Hard Limit)
Cycle 1: Structural contrast (2–3 directions)  
Cycle 2: Axis refinement (density/type/image/surface)  
Cycle 3: Hierarchy and rhythm (spacing/alignment/anchors)

After Cycle 3 → selection required.

No infinite iteration.

---

## Merge Phase (Pick & Mix)
User selects:
- HERO:A
- SERVICES:B
- etc.

Generate `direction-merge.html`.

Merge may:
- harmonize spacing
- normalize baseline density
- align surface language

Merge may NOT:
- introduce new concepts
- redesign the direction

Merge is compositional, not creative.

---

## DNA Lock Protocol
After merge approval:
1) write `dna-diff.md` describing v1→v2 changes
2) update `active-dna.md` to v2
3) mark DNA as locked for production

---

## Vocabulary Extraction
If new vocabulary emerges:
- append to Prompt Bible
- categorize under the relevant axis
- do not overwrite existing entries

---

## Token Policy
Tokens are allowed here.
Tokens must be spent on:
- structure exploration
- density testing
- typography/image interplay

Tokens must not be spent on:
- framework setup
- component abstractions

---

## Transition
After DNA v2 is locked:
- go to 19 Section Prototyper for proof
- then production pipeline

If someone tries to run 19 without DNA v2:
- redirect back to 18.5.
